# ADR-0029: приём входящих заметок с фоновой записью

Статус: accepted, 2026-09-14, MD-453.

## Причина

Пользователь попросил сократить ожидание сохранения в ChatGPT: агент передаёт
небольшую заметку один раз, получает подтверждение приёма и продолжает ответ.
Задержка обработки и редкие технические сбои допустимы. Проверку целостности
и актуальных прав выполняет сервер.

## Решение

Для новых добавочных заметок используется обычный MCP tool `enqueue_note`.
Сервер сохраняет точный текст в object storage и квитанцию в durable metadata
до ответа. `queued` означает принятые данные, а `committed` — созданную
каноническую ревизию. `get_note_status` доступен для диагностики; регулярный
опрос или read-back со стороны ChatGPT не требуются.

Обработчик создаёт один Source в `raw/inbox/` через существующий validated
changeset. Он повторно проверяет credential, ACL, исходную write generation,
целостность payload и HEAD CAS. Изменение HEAD допускает ограниченный повтор
добавочной операции. Идемпотентность предотвращает повторную запись после
неизвестного результата. Ошибка сохраняет payload и диагностический статус.

Решение дополняет ADR-0028: новый разговорный факт может поступать через
очередь независимо в каждый разрешённый Mind. Точные изменения, удаления и
перенос с проверяемыми source references используют `commit_changeset`.
Ни транзакции между Minds, ни синхронизации копий не появляется.

## Границы

- Текст до 64 KiB, заголовок до 200 символов; не более 32 незавершённых
  заметок на Mind. Большие файлы используют существующий file ingress.
- Sites запускает первоначальную обработку через bounded `waitUntil`.
  Это не автономный scheduler и не гарантия продолжения после потери isolate.
  Точный повтор приёма или явное operator recovery могут возобновить работу.
- Встроенная серверная модель не анализирует и не переписывает заметки.
- MCP Tasks и универсальное автоматическое сохранение каждого сообщения
  ChatGPT не заявляются. Агент должен действительно вызвать инструмент.
- Backup сохраняет квитанции и payload; offline restore сохраняет данные,
  но не возобновляет работу старых credentials.

## Проверка

Контракт проверяется тестами durable receipt, restart, идемпотентности,
потери ответа commit, конкурентного HEAD, отзыва write generation и backup
незавершённой заметки. Hosted acceptance отдельно должна подтвердить новый
tool в реальном ChatGPT и появление заметки без следующего сообщения.
