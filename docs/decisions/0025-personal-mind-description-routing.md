# ADR-0025: описание Personal Mind и тематическое использование двух Minds

Статус: accepted, 2026-09-05. Принято пользователем; реализация не выполнена.

## Контекст

Direct-request-only Personal Mind из ADR-0024 не использует тематические знания
без повторяющихся просьб. Пользователь хочет объяснять интересы агенту своими
словами и применять одинаковые критерии выбора личного и обычных Minds.

## Решение

`disabled | read | read_write` определяет разрешённые действия, а description —
темы их автоматического применения. Personal получает опциональное description.
Без него сохраняется чтение и запись только по прямой просьбе; непустое описание
разрешает тематическое чтение и, при `read_write`, автоматическое сохранение
явно обсуждённых долговечных знаний. Пустое значение эквивалентно отсутствующему.

Пользователь настраивает Personal description через узкую MCP metadata operation:
агент формулирует текст по прямой просьбе о настройке и сообщает read-back.
Это не разрешение менять mode, scopes, обычные Minds или access control.

У principal остаётся максимум один обычный writable Mind плюс независимый Personal.
При соответствии обоим описаниям агент читает оба и сохраняет подходящее новое
обсуждённое знание в оба отдельными операциями. Две копии не синхронизируются.
Частичный успех сообщается явно. Автоматический перенос извлечённых Personal
сведений в ordinary Mind с другими читателями запрещён без прямой просьбы.

## Последствия и границы

Description остаётся недоверенной service metadata, вне OKF/content history.
Current ACL, scopes, generations, routing version, HEAD CAS, idempotency и
полная валидация сохраняются. Existing Personal descriptions мигрируют в null;
автоматический профиль не выводится из corpus. Новая возможность не означает,
что текущий runtime или установленный плагин её уже поддерживают.

Это изменение заменяет Personal-specific правила пунктов 4–8 и последствия
[ADR-0024](0024-principal-mind-usage-modes-and-automatic-save.md), сохраняя
независимые write lanes и все остальные ограничения.
