# ADR-0031: один MCP endpoint

Статус: accepted, 2026-09-19. Прямое решение владельца: удалить поддержку
старого протокола и оставить один MCP.

## Решение

Единственный content MCP endpoint — `POST /api/mcp`, протокол `2026-07-28`.
Он обслуживает весь текущий каталог, включая файловый вход ADR-0030.
`/api/mcp/2025-11-25` и `/api/mcp/apps` не обслуживаются и возвращают 404;
redirect, negotiation downgrade и скрытый legacy fallback отсутствуют.

Удаляются legacy initialize/initialized bridge, выбор MCP profile в настройках,
второй вариант клиентской конфигурации и legacy ветви активных проверок.
Проверки доступа, OAuth audience `/api/mcp`, scopes, current ACL, история,
содержимое Minds и файловый transport не меняются.

Клиенты должны поддерживать текущий протокол. Старую сохранённую URL-настройку
следует заменить на `/api/mcp`; существующие современные подключения не
требуют смены URL или расширения полномочий.

Исторические отчёты и receipts сохраняются как свидетельства прошлых версий,
но не задают текущий release gate. Это решение заменяет требования отдельного
compatibility endpoint в прежних спецификациях и ADR-0030. Совместимость
форматов хранимых данных к этому удалению не относится.

## Проверка

Проверить современный discovery, каталог, чтение и запись с прежними ACL/CAS,
отрицательные запросы к удалённым endpoint, единственный URL в настройках и
read-only self-check. UAT должен подтвердить тот же artifact и реальные ответы
маршрутов; локальная проверка не является hosted evidence.
