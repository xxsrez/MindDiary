# ADR-0027: полный серверный журнал измерений для автономной приёмки

Статус: accepted implementation direction, 2026-09-06, MD-406 / Epic MD-400.
Это выбор реализации в рамках порученной пользователем автономной тестовой
среды; успешная живая проверка отдельно фиксируется в плане исполнения.

## Причина

В нескольких hosted прогонах выдача Sites последних 100 Worker events не
содержала полного набора событий отдельных успешных запросов. В v9 события
появились после минутного предела, а v10 остановился и при двухминутном
ожидании. Более частое чтение и ограничение пакетов не обеспечили полноту.
Это ограничение наблюдаемого способа сбора, не доказательство причины внутри
провайдера и не основание объявлять отсутствующие измерения успешными.

## Решение

Только отдельный acceptance adapter подключает существующий
`observabilityWriter` общего runtime. Он продолжает обычную запись в console
и сохраняет исходные latency events подписанного benchmark-запроса в D1.
События поступают из общего измерителя: времена, результаты и request IDs
не вычисляются повторно и не принимаются через внешний ingestion endpoint.
После окончания product response запись в D1 подтверждается до отправки
ответа клиенту. Её накладные расходы входят в наблюдаемую клиентом задержку;
серверные временные окна общего runtime остаются прежними.

Журнал связывает события с активным test run, correlation ID, compiled
candidate SHA и adapter digest. Максимум 16 событий на запрос и 4096 на run;
очистка и TTL recovery удаляют журнал вместе с run. Неподписанные запросы,
неуспешная авторизация и обычная сборка продукта не создают такие записи.
Секреты, headers и corpus не входят в закрытую проекцию телеметрии.

Агент выгружает все страницы таблицы через настоящий read-only Sites D1
control-plane tool после завершения выборки. Новый versioned capture явно
называет этот источник; он не выдаёт строки D1 за Worker log envelopes.
Проверяются непрерывная pagination, отсутствие truncation, run/candidate/
adapter identity, уникальность событий и digest каждого исходного ответа.
Прежние captures остаются проверяемыми по прежнему контракту.

Все 273 samples, минимум 20 warm samples на серию, подписи запросов, точные
correlation/request IDs, полнота операций, калибровка часов, budgets и cleanup
сохраняются. Подмена значений, чужая версия/таблица/run, пропуск страницы или
события дают failure. Исторические MD-394/399 и platform canaries не изменяются.

## Проверка

Нужны отрицательные tests неподписанных/чужих запросов, лимитов, неполной
выгрузки, подмены событий и cleanup; затем настоящий hosted capture и строгий
performance gate. Наличие этой ADR не означает, что эти проверки пройдены.
