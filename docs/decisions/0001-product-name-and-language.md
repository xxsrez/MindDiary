# ADR-0001: название продукта и пользовательская лексика

Статус: accepted, 2026-08-05.

## Контекст

Проекту нужна лексика, которую массовый пользователь понимает без знакомства с
OKF, MCP, knowledge graphs или архитектурой хранения. Прежнее техническое
рабочее имя описывало инфраструктурную идею, но не давало самостоятельного
человеческого образа. Термины `KnowledgeSpace` и `KnowledgeEntry` точны для
доменной модели, однако слишком технические для основного интерфейса и
коммуникации.

## Решение

- Название продукта: **Mind Diary**.
- Один пользовательский knowledge space называется **Mind**; множественное
  число — **Minds**.
- Одна пользовательская запись знания называется **Memory**; множественное
  число — **Memories**.
- Базовая смысловая формула бренда: **Build a Mind from Memories.**

Техническая доменная модель не переименовывается механически:

| Пользовательский термин | Технический термин |
|---|---|
| `Mind` | `KnowledgeSpace` / короткое техническое `Space` |
| `Memory` | `KnowledgeEntry` как пользовательский umbrella term |
| `Memories` | Набор entries; `Source`, `Index` и `Log` сохраняют отдельные технические правила |

OKF 0.2 не задаёт нормативную entity `Asset`. Будущие non-Markdown files могут
получить producer-defined технические типы вроде `BundleFile`/`OpaqueAsset`
только после отдельной specification; пользовательский umbrella term
`Memories` сам по себе их не вводит.

В пользовательском тексте `Mind` и `Memory` пишутся с заглавной буквы, когда
обозначают сущности продукта. Обычные значения слов mind и memory оформляются
по правилам языка и не считаются API-терминами.

## Последствия

- Product copy использует действия `Create a Mind`, `Open a Mind`, `Add a
  Memory`, `Ask this Mind` и `Share a Mind`.
- Архитектурные спецификации продолжают использовать `KnowledgeSpace`,
  `KnowledgeEntry`, `space_id`, `space_handle` и `SpaceRevision`, чтобы брендовая
  метафора не размывала security и storage semantics.
- `Memory` нельзя смешивать с conversation memory, Amazon Bedrock AgentCore
  Memory или model context. Для них используются точные технические названия.
- Каноническое имя GitHub repository и локальной папки — `MindDiary`.
- Пользовательское имя сайта — `Mind Diary`; preferred lowercase slug для
  Sites, deployment и package identifiers — `mind-diary`, если конкретная
  платформа позволяет его выбрать.
- Точный production domain остаётся отдельным решением. Product slug не
  заменяет `space_handle` и не меняет canonical URL model отдельных Minds.

## Рассмотренные направления

- `Mindarium` было отклонено как искусственное и непонятное массовой аудитории.
- Биологические, грибные, музейные и космические метафоры были отклонены как
  требующие обучения новой лексике.
- `Mind Diary → Mind → Memory` выбрано за понятность, спокойный эмоциональный
  образ и естественные пользовательские глаголы.

Базовые визуальные и речевые правила находятся в
[руководстве по айдентике](../brand.md).
