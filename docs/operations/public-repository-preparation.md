# Подготовка публичного репозитория

Запрос владельца: сохранить историю всех веток и тегов, удалив чувствительные
данные. Публичность GitHub меняется отдельно, после завершения очистки.

## Что считается приватным

Личные и рабочие email авторов, домашние пути, UUID старых claim-токенов,
адреса и идентификаторы конкретных сред, ссылки на личные разговоры,
идентификаторы пользовательских плагинов и отчёты о реальных пользовательских
копиях или проверках аккаунта не входят в публичный исходный код.

Для примеров используйте зарезервированные домены и синтетические значения.
Фактические deployment settings и частные отчёты храните вне Git, например в
игнорируемом приватном каталоге. Отсутствие API-ключа не делает claim-токен
безопасным: действующие полномочия проверяют и при необходимости отзывают
отдельно от переписывания истории.

## Локальная защита

Нужен Node.js из repository baseline. В каждом новом клоне выполните:

```sh
npm run setup:publication-hooks
npm run test:publication
npm run check:publication
```

Установщик использует абсолютный `core.hooksPath`, общий для связанных
worktrees, и не заменяет посторонние hooks без разбора. Для Git identity
настройте свой GitHub noreply-email; не переносите адрес другого разработчика.

- `pre-commit` проверяет содержимое Git index, включая уже отслеживаемые файлы.
- `commit-msg` проверяет сообщение и effective author/committer email.
- `pre-push` проверяет всю историю передаваемых commit/tag tips, включая
  удалённые из HEAD файлы и сообщения предков.
- Workflow `Publication hygiene` повторяет проверку полной доступной истории
  и index. Он выполняется после получения данных GitHub и сам по себе
  не предотвращает первоначальную отправку.

Вывод проверки содержит категории и object IDs, но не найденные значения.
Shallow clone и недоступные объекты не дают положительного результата.
Это проверка известных категорий, а не доказательство отсутствия любых
секретов или приватных сведений. Hooks можно обойти; они не заменяют
серверные ограничения и проверку новых документов человеком.

## Перенос очищенной истории

1. Снять точный список remote refs и отдельно сохранить незакоммиченную работу.
2. В независимой копии переписать blobs, сообщения, author/committer/tagger
   metadata. Сохранить родителей и все branch/tag tips; старые editor snapshots
   и refs других локальных worktrees не публиковать.
3. Сверить каждый исходный branch/tag с commit-map, проверить всю очищенную
   историю и отсутствие исходных чувствительных значений.
4. Перепривязать исполняемые historical fixtures к новым SHA и digest.
   Старые hosted receipts не превращаются в подтверждение новых SHA:
   обезличенные отчёты и placeholder settings не являются deployment evidence.
5. Перед remote rewrite согласовать точный ref-план. Использовать отдельные
   refspecs, atomic push и `--force-with-lease` с ожидаемым SHA каждой ветки.
   Не использовать безусловный `push --mirror`: локальная копия содержит
   дополнительные служебные refs.
6. Проверить Actions runs/logs, pull request refs, releases, artifacts и forks.
   Замена branch tips не удаляет эти поверхности. При необходимости очистить
   их отдельно; PR refs и кэшированные commit views требуют участия GitHub.
7. Получить свежий клон с GitHub и повторить проверку. Только после завершения
   оставшихся шагов менять visibility.
8. Старые клоны и worktrees нельзя снова merge/push в очищенную историю.
   Перенести только проверенный patch незакоммиченной работы или создать новый
   клон. Приватный исходный архив никогда не добавлять в публичный Git.

Публичные конфигурации после обезличивания содержат синтетические targets.
Они предназначены для чтения и локальных тестов, не для публикации в прежнюю
среду. Настройка настоящего target требует приватного deployment configuration
и отдельной проверки; восстановление реальных IDs в tracked файлах запрещено.

[GitHub: удаление чувствительных данных](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)
описывает ограничения force push, PR refs, cached views и чужих клонов.
