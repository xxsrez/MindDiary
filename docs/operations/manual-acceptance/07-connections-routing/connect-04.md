# CONNECT-04 — Отзыв при одновременной выдаче credentials

Источник: локальное ревью 2026-11-03; возможна гонка между выборкой mirrors
для отзыва и вставкой новой access row. Нужен тестовый клиент и управляемые
барьеры выдачи/отзыва; без них случай blocked. Локальные тесты не подтверждают
работу выбранного hosted deployment.

## Шаги

1. В отдельном тестовом подключении приостановить refresh вокруг создания access row и mirror.
2. Одновременно начать отзыв подключения, затем по очереди освободить оба процесса.
3. Проверить, что после успешного отзыва новый credential не работает и уже начатая операция не проходит финальную проверку доступа; повторить для `personal:configure` и отложенной обработки заметки.
4. Вызвать отказ хранилища при отзыве owner после закрытия grant; убедиться, что refresh и новая аутентификация закрыты, а незавершённый отзыв можно повторить даже без активных access rows.
5. Приостановить два consent на разных дополнительных scopes после чтения одной версии grant. После завершения первого второй должен получить конфликт и не потерять уже согласованный scope; повторный consent должен сохранить оба.

## Ожидается

Успех отзыва означает закрытие новых запросов и fencing всех затронутых
операций. Ошибка или неопределённый результат не выдаются за успех: временный
сбой RFC 7009 revoke возвращает `503`, а клиент не считает отзыв завершённым.
