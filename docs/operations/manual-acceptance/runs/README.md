# История ручных прогонов

При создании каталога прогонов нет. Этот файл описывает порядок хранения,
а не является результатом проверки.

Для каждого фактического прогона создать папку `YYYY-MM-DD-short-name` и
`README.md` по [шаблону](../templates/run.md). Добавить ссылку на прогон сюда.
Обычный небольшой прогон хранится в одном файле; подробные результаты при
необходимости — в файлах по ID внутри папки с ссылками из отчёта.
Не создавать заранее пустые папки или результаты «passed».

Время начала/конца и длительность записывает исполнитель. Подготовка группы и
очистка учитываются отдельно от карточек. После выполнения обновить здесь
краткую таблицу типичных длительностей по ID: число наблюдений, медиана завершённых
попыток, диапазон, последняя дата; timeout учитывать отдельно как достижение лимита,
не как нормальную длительность. Пока измерений нет, оценки неизвестны.
Разные размер данных, клиент или среду не объединять в одну оценку без пояснения.

При первом планировании 10 минут — только верхний default на случай, не прогноз.
Не увеличивать лимиты автоматически из-за зависаний. Повторяющиеся timeout —
повод пересмотреть сценарий или завести дефект.

Краткую статистику обновлять после завершённого прогона, сохраняя исходные записи.
Это ручной порядок ведения каталога; автоматический сборщик здесь не реализован.
